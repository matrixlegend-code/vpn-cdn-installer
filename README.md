## Что делает скрипт

VPN CDN Installer подготавливает сервер и собирает рабочую схему доставки VPN-трафика через CDN. Пользователь выбирает архитектуру, панель и CDN-провайдера, после чего установщик сам разворачивает необходимые службы и выводит готовые данные для подключения.

Основной транспорт — **VLESS XHTTP Packet-Up**. Клиент обращается к домену CDN, CDN передаёт запросы на origin, а Nginx направляет XHTTP-трафик в Xray:

```text
Клиент → CDN-провайдер → Nginx/Caddy → Xray → Интернет
```

Для каскадной схемы добавляется промежуточный relay:

```text
Клиент → CDN-провайдер → Relay → Exit-нода → Интернет
```

## Что устанавливается автоматически

- Docker и Docker Compose, когда они требуются выбранной панелью;
- Remnawave или 3x-ui;
- Xray с VLESS XHTTP Packet-Up;
- Nginx и Caddy для панели, origin и подписок;
- TLS-сертификаты для используемых доменов;
- CDN inbound с отдельным профилем выбранного провайдера;
- сетевые параметры Linux, BBR и TCP-настройки;
- firewall и необходимые правила доступа;
- geo-файлы и правила маршрутизации Xray;
- подписки и ссылки для клиентских приложений;
- страница-заглушка для обычных веб-запросов;
- проверка служб, портов, Nginx и health endpoint.

## Режимы установки

### 1. Панель и нода на одном сервере

Самый простой вариант. Панель, Xray, CDN origin и подписки размещаются на одном VPS. Подходит для быстрого запуска и небольшой инфраструктуры.

```text
CDN → один VPS: панель + origin + Xray
```

### 2. Панель и удалённая нода

Панель остаётся на основном сервере, а CDN origin и Xray-нода устанавливаются на отдельном VPS. Подходит для нескольких локаций и разделения управления и трафика.

```text
Панель управления ↔ удалённая нода ← CDN
```

### 3. CDN для существующей панели

Скрипт добавляет CDN inbound и необходимые веб-конфигурации к уже работающей инфраструктуре. Полная переустановка панели не требуется.

## Поддерживаемые CDN

Каждый CDN настраивается отдельной веткой: отличаются тип origin, домены, TLS и параметры ресурса. Скрипт не использует одну универсальную инструкцию для всех провайдеров.

### VK Cloud

- origin работает по HTTP;
- поддерживается обычная и каскадная схема;
- установщик создаёт XHTTP inbound и конфигурацию Nginx;
- подходит для пользователей с готовым аккаунтом VK Cloud CDN.

### Yandex Cloud

- поддерживается HTTPS-соединение до origin;
- настраиваются домен источника и TLS;
- подходит, когда требуется шифрование на участке CDN → origin;
- поддерживается работа через отдельную ноду.

### TurboFlare CDN

- origin работает по HTTPS на порту 443;
- используется отдельный XHTTP-путь `/static/getFile/video/segment.ts`;
- TurboFlare управляет всей DNS-зоной домена через собственные NS-серверы;
- сертификат для edge выпускает сам TurboFlare;
- отдельный режим 4 помогает перенести существующий домен и проверить делегирование NS;
- перед сменой NS необходимо перенести в TurboFlare остальные DNS-записи зоны.

### Beeline CDNvideo

- используется домен, выданный CDNvideo;
- предусмотрен отдельный профиль origin и HTTP-заголовков;
- поддерживаются сценарии Remnawave и 3x-ui;
- установщик выводит параметры, которые нужно перенести в кабинет CDNvideo.

### Timeweb CDN

- источник задаётся как IP-адрес сервера на порту 80;
- HTTPS до origin выключается;
- Timeweb выдаёт технический домен вида `xxxx.cdn.twcstorage.ru`;
- пользовательский CDN-домен направляется CNAME-записью на технический домен;
- кеширование и Gzip/Brotli выключаются;
- параметр «Игнорировать параметры запроса» должен быть выключен;
- стандартный клиентский путь: `/content/media/stream.m3u8`.

После установки скрипт показывает конкретный IP origin, CDN-домен, DNS-запись и настройки ресурса Timeweb.

### Selectel CDN

- создаётся ресурс типа «Статика» с HTTPS origin на порту 443;
- CDN выдаёт технический домен вида `xxxx.selcdn.net`;
- для длинных XHTTP-потоков увеличиваются таймауты соединения и ответа;
- кеширование, оптимизация изображений, Brotli и Gzip выключаются;
- дополнительно разрешаются методы DELETE и POST, основной uplink использует DELETE;
- используется отдельный XHTTP-путь `/api/uploadFile/`;
- персональный домен не должен совпадать с доменом origin, иначе возникает цикл запросов.

## Сравнение CDN

| CDN | Соединение до origin | Источник | Основное отличие |
|---|---|---|---|
| **VK Cloud** | HTTP | Домен origin | Высокая скорость и поддержка каскада |
| **Yandex Cloud** | HTTPS | Домен origin | TLS между CDN и сервером |
| **TurboFlare CDN** | HTTPS `:443` | Домен с делегированием NS | Управление DNS-зоной и сертификатом на стороне TurboFlare |
| **Beeline CDNvideo** | HTTP/HTTPS | Выданный CDN-домен | Отдельный профиль провайдера |
| **Timeweb** | HTTP `:80` | IP-адрес сервера | Простая схема origin и технический CNAME |
| **Selectel CDN** | HTTPS `:443` | Домен origin | Технический `*.selcdn.net`, таймауты и методы DELETE/POST |
